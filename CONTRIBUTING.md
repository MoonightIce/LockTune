# Contributing

LockTune is intentionally dependency-light and local-first.

## Before changing code

1. Read docs/product-scope.md and docs/architecture.md.
2. Link the work to its Linear issue.
3. Keep Google Calendar optional and music playback independent from network
   state.
4. Do not add private macOS APIs, telemetry, user music, OAuth tokens, real
   OAuth client credential values, or private calendar data. Empty build
   settings and local/release injection points are allowed.

## Tests

Behavior tests live at public seams. Use one red-green vertical slice at a time.
Core tests run with:

    swift test

The app target builds with:

    xcodebuild -project LockTune.xcodeproj -scheme LockTune \
      -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build

Private music is for local read-only acceptance only. Its directory path,
filenames, and metadata must not be committed or logged. Public fixtures must
be generated by the project or carry an explicit redistribution license.
